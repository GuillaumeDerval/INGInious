# Internationalisation (legacy frontend)

## Summary

* **Platform UI strings** use plain GNU gettext (`gettext.translation('messages',
  …/frontend/i18n, [lang])`) with Babel only as the extraction/compilation tool
  (`frontend/babel.cfg`). `_()` is a single function (`frontend/i18n/__init__.py:13-15`) that
  reads **`session.language`** on every call. It is exposed as a Jinja global
  (`app.py:179`) and as a Python builtin (`i18n/__init__.py:38`). There is no
  `jinja2.ext.i18n`, no `{% trans %}`, no plural forms (`ngettext` is never used), and no
  lazy strings.
* **Languages** (`i18n/__init__.py:17-30`, in this order): `en` English (the source language,
  `NullTranslations`), `de` Deutsch, `el` ελληνικά, `es` Español, `fr` Français, `he`
  עִבְרִית, `nl` Nederlands, `nb_NO` Norsk (bokmål), `pt` Português, `vi` Tiếng Việt. The
  directories `pt_BR` (empty .mo) and `wa` (19 messages, .mo only) exist but are **not
  enabled**.
* **Language selection**: stored in the Mongo-backed session (`sessions.language`, default
  `""`). On every page request (`INGIniousPage._pre_check`, `pages/utils.py:33-39`), a
  `?lang=<code>` query parameter (when valid) overrides the session. Otherwise, if the session
  has no language yet, the best `Accept-Language` match is used (default `en`). At login,
  the session takes the user's `users.language` (`user_manager.py:193`, default `"en"`). The
  profile page writes `users.language` and the session (`pages/preferences/profile.py:72-75,110-111`).
  `?lang=` does **not** update the user document.
* **Course content** (course.yaml / task.yaml strings) is translated with per-course gettext
  catalogs: compiled `.mo` files named `<lang>.mo` in `$i18n/` folders of the course and the
  task. The **msgid is the full original string** (e.g. a whole RST context). This is done
  *before* RST rendering.
* **JS**: there is no JS i18n framework. Translated strings reach JS through hidden DOM
  spans (`#messages` in `task.html:321-326`), strings interpolated in inline `<script>`
  blocks, server-built HTML in JSON responses, and `Intl.DateTimeFormat`/moment locale for
  dates. Several JS strings are hard-coded in English.
* **RTL**: there is a magic msgid `"__is_rtl"`. When it translates to `"true"` (only `he`),
  `layout.html` loads `bootstrap-rtl.min.css`, `INGInious-rtl.css`, `all-minified-rtl.js`
  and `bootstrap-rtl.min.js`. `<html lang="en">` is hard-coded and never gets `dir="rtl"`.
* **Catalog**: `messages.pot` has **789 msgids** (+ header), POT-Creation-Date 2025-04-17.
  Completeness: fr 789/789 (100%), nb_NO 769 (97.5%), he 711 (90.1%), es 558 (70.7%),
  vi 294 (37.3%), pt 269 (34.1%), de 256 (32.4%), el 196 (24.8%), nl 40 (5.1%).
  Fuzzy entries are excluded from the .mo files and fall back to English.

## 1. Platform catalog

### 1.1 Files

```
legacy/inginious/frontend/babel.cfg          [python: inginious/frontend/**.py]
                                             [jinja2: inginious/frontend/**.html]
                                             extensions=jinja2.ext.i18n   (extraction only)
legacy/inginious/frontend/i18n/messages.pot
legacy/inginious/frontend/i18n/<lang>/LC_MESSAGES/messages.{po,mo}
legacy/inginious/agent/mcq_agent/i18n/...    (separate 5-msgid catalog, see §5)
```

The workflow is documented in `legacy/doc/dev_doc/extensions_doc/i18n.rst`:
`pybabel extract -F inginious/frontend/babel.cfg ./ -o …/messages.pot`, then
`pybabel update` and `pybabel compile` per language. The `.mo` files are committed and loaded
at import time (`i18n/__init__.py:32-34`). A missing `.mo` for an enabled language crashes
the import.

### 1.2 Runtime (`frontend/i18n/__init__.py`)

```python
def gettext(text):
    language = session.language if flask.has_app_context() else ""
    return _translations.get(language, _gettext.NullTranslations()).gettext(text) if text else ""
```

* An empty or falsy `text` returns `""`. This avoids returning the catalog header for `""`.
* An unknown language, or no app context, means no translation.
* Strings are formatted **after** translation with `str.format` (`_("… {} …").format(x)`,
  or named fields such as `{score}`, `{submissionid}`). 65 msgids are marked
  `python-format`/`python-brace-format`. Many msgids contain HTML (e.g.
  `"<b>Your submission has been sent...</b>"`, `"<b>Parsing failed</b>: <pre>{}</pre>"`). The
  new app keeps the HTML inside these messages; `t()` itself does not escape, so callers
  HTML-escape interpolated text (`escapeHtml`) and the resulting HTML is passed through the
  sanitizer before it is displayed.
* `app.py:114` publishes `config.LANGUAGES = available_languages` (an ordered dict code → native name).

| Step | Code | Behaviour |

| Login | `user_manager.py:182-193` `connect_user` | `session.language = user.language` (the user document wins over the browser and `?lang`). |
| Registration | `pages/register.py:98` | new `users.language = session.language` |
| Profile | `pages/preferences/profile.py:72-75,110-111`, `templates/preferences/profile.html:66-71` | `<select name="language">` listing `config.LANGUAGES` (native names). An invalid value becomes `en`. It updates `users.language` and the session. |
| Language menu (anonymous, non-LTI only) | `templates/layout.html:170-177` | Label `{{ _("English") }}` (i.e. the current language's name *as translated in its catalog*). ## 3. Course/task content translation (`$i18n`)

* **Course** (`courses.py:300-319` `Course.get`): it lists `<course>/$i18n/*.mo` (not
  recursive). The file stem is the language code (`fr.mo` → `fr`). Each file is loaded with
  `gettext.GNUTranslations(fd)` and cached by mtime (`fetch_or_cache`,
  `common/filesystems/__init__.py:151-157`). `Course.gettext(language, text)`
  (`courses.py:108-115`) returns `""` for empty text and otherwise uses the catalog for
  `language` or the identity.
  * Translated: `get_name`, `get_description` (then RST), tag `get_name`, and tag
    `get_description` (`common/tags.py:30-46`). **Bug**: `get_description` translates and
    returns the *name*. Also `templates/course_admin/stats.html:141` additionally passes
    the tag name through the platform `_()`.
  * Not translated: task-dispenser section titles (`toc`), the marketplace (which uses
    per-language dicts `name`/`short_desc`/`description` with a `default_language`,
    `marketplace_courses.py:55-75`), static pages (separate `<page>.<lang>.yaml` file,
    `pages/utils.py:220-224`).
* **Task** (`tasks.py:217-245` `Task.get`): it searches, in this order,
  `<task>/$i18n`, `<task>/student/$i18n`, `<course>/$common/$i18n` and
  `<course>/$common/student/$i18n`, and **only the first existing directory is used** (`break`
  at l.242: no merging, so a task folder without its own `$i18n` uses the course-wide
  `$common` one). The same catalog dict is passed to every problem (`tasks.py:166`).
  * Translated: `get_name`, `get_context` (before the `task_context` plugin hook and RST),
    `get_authors`, problem `get_name`, problem `header`, multiple-choice choice `text`
    (`task_problems.py:209`), and the MCQ `feedback`/`success_message`/`error_message`
    (in the MCQ agent, `common/tasks_problems.py:352-393`).
  * The msgid is the **exact YAML string** (including newlines and RST markup). Any edit of
    the source text silently breaks the translation.
* **Grading containers** translate their own feedback (`legacy/doc/teacher_doc/translating.rst`:
  `inginious_container_api.lang.init()` installs `_` from `/task/lang/<LANGUAGE>/LC_MESSAGES/messages.mo`;
  `feedback-msg-tpl` templates have `_()`). The frontend does **not** translate feedback.
* The repository's demo/test courses ship no `$i18n` folders (nothing under
  `examples/demo-tasks` or `infra/tasks`), so tests must create their own `.mo`.
* There is no UI for managing course translations. `.mo` files are uploaded like any other
  task file (task file editor/WebDAV).

## 4. JavaScript strings

* There is no `i18n.js`, no JSON dictionary, and no `_()` in `static/js/*.js`.
* Mechanisms in use:
  1. Hidden spans that JS reads with `.text()`: `task.html:321-326` `#answerall`,
     `#internalerror`, `#invalidext` (`"{} has not a valid extension."`, with `{}` replaced in
     JS, `task.js:237`) and `#filetooheavy` (`task.js:247`).
  2. Inline `<script>` blocks with `{{ _("…") }}` interpolated into JS string literals:
     `lti/deeplink.html` (5 strings), `course_admin/submissions.html`
     (`'Waiting'`), `course_admin/task_edit.html` (`delete_subproblem_message`).
  3. HTML/text built server-side and returned in JSON (`title`, `text` of the submission
     JSON in `pages/tasks.py:173-343`: queue messages, result titles, errors).
  4. Server-rendered templates for modals/rows that JS clones (studio).
* Hard-coded English in JS: `"Succeeded"`/`"Failed"` in `updateTaskStatus`
  (`task.js:182,386,395`), `"Close"` sr-only text in `getAlertCode` (`task.js:597,625`),
  `"Error"` passed as an alert title (`task.js:266`), and the debug-info labels.

## 5. Other catalogs

* **MCQ agent** (`agent/mcq_agent/__init__.py:28-33,72-127`). It has its own catalog
  (`agent/mcq_agent/i18n`, 5 msgids: "Wrong answer. Make sure to select all the valid
  possibilities", "Wrong answer", "Correct answer", "You have {} wrong answer(s).", "Among
  them, you have {} invalid answers in the multiple choice questions") and loads every
  sub-directory present: de, es, fr, he, nb_NO (5/5 translated each). The language is
  `inputdata["@lang"]`. Task catalogs are looked up like the frontend (first existing `$i18n`
  dir), but only `<lang>.mo` is loaded. Note that `"No subproblems defined"` is not translated.
* **Plugins** have no catalogs of their own. They use the global builtin `_` (strings are
  extracted into the frontend `messages.pot` through the `inginious/frontend/**` globs:
  auth and upcoming_tasks are present, contests is missing).
  `plugins/ltibestsubmission` uses `problem.gettext(session.language, …)` for task strings.

## 6. RTL handling

* `layout.html:23-31` (CSS), `:78-80` (`all-minified-rtl.js` vs `all-minified.js`) and
  `:91-93` (`bootstrap-rtl.min.js`) test `_("__is_rtl") == "true"`.
* Only `he` sets `"true"`. nb_NO translates it to the literal `"__is_rtl"` (LTR).
* `<html lang="en">` (`layout.html:8`) is fixed for every language, with no `dir`
  attribute: the RTL CSS does the mirroring.

## 7. Requirements for the rewrite

1. **Language list and codes**: support exactly `en, de, el, es, fr, he, nl, nb_NO, pt, vi`
   (same codes, because they are stored in `users.language`, `sessions.language` and sent
   as `@lang` to graders and to course `$i18n/<code>.mo` lookups). Show them with the same native
   names. Keep `pt_BR`/`wa` disabled unless the catalogs are completed.
2. **Resolution order** (parity): explicit `?lang=` (valid codes only; persist it in the
   session) > session value > on first visit, `Accept-Language` best match (with the
   prefix/region matching shown in §2) > `en`. On login, the user's stored language replaces
   the session value. The profile change writes both. Recommended improvements that keep
   compatibility: preserve the other query parameters in the language switcher, offer it to
   logged-in users, and set `<html lang>` and `dir="rtl"` for `he`.
3. **Catalog**: migrate the 789 msgids, with their existing translations from the `.po` files,
   into the new i18n system (e.g. convert `.po` → JSON for svelte-i18n / Paraglide /
   typesafe-i18n, or keep gettext `.po` with a JS gettext runtime). Keep English source
   strings as keys (or keep a msgid→key map) so the existing translations can be re-imported.
   Keep the placeholder semantics (`{}`, `{score}`, …) and the HTML inside messages, and
   exclude fuzzy entries. Add a CI completeness report per language.
4. **Fallback**: a missing translation shows the English source string (never an empty string).
   An empty msgid gives `""`.
5. **RTL**: derive the direction from the locale (he → rtl) instead of the `__is_rtl` hack,
   but keep `he` rendering mirrored.
6. **Course content**: implement GNU `.mo` parsing (or `.po`) in TypeScript. Load
   `<course>/$i18n/<lang>.mo` for the course name/description/tags, and for tasks use the
   **first existing** of `<task>/$i18n`, `<task>/student/$i18n`, `<course>/$common/$i18n`,
   `<course>/$common/student/$i18n`. The msgid is the exact source string. Translate before
   RST rendering. Cache by file mtime. Apply it to: course name, course description, tag names
   (and fix the tag description bug knowingly or keep it, then document the choice), task name,
   context, authors, problem names, headers, choice texts. MCQ feedback stays with the grader/agent.
7. **Grader language**: send `@lang` = the session language for normal submissions and
   the user's stored language for replays (as legacy does).
8. **JS strings**: all client-side strings (including the legacy hard-coded
   "Succeeded"/"Failed"/"Close"/"Error") must come from the same catalog. Date/time
   formatting uses `Intl.DateTimeFormat([lang, "en"], {dateStyle:"short", timeStyle:"medium",
   timeZone: user timezone})`.
9. **Static pages**: serve `<page>.<lang>.yaml` when present, else `<page>.yaml`.
10. **Tests**: switching language with `?lang=` and the profile, Accept-Language on the first
    visit only, the login override, the he RTL stylesheet/`dir`, course/task `.mo`
    translation (including the `$common` fallback and the first-directory-wins rule),
    untranslated strings falling back to English, and `@lang` propagation to the grader.
